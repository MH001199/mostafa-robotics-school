# Community and Contributions

[Start Learning](student-course/README.md) · [Student Projects](resources/student-projects.md) · [Code of Conduct](CODE_OF_CONDUCT.md)

Open an issue for a reproducible wiring error, code bug, lesson improvement, or future project request. Report the exact lesson, kit, expected behavior, observed result, and a minimal reproduction. Include photos only when you have permission and they do not expose personal information.

For a pull request, describe the student impact, keep the relevant sketch and pin table together, and preserve the existing hardware routes. Check the documentation and list which sketches you compiled. State whether you used a simulator or physical components. Update [image attribution](IMAGE-SOURCES.md) for any new asset.

## Discussions setup for maintainers

Once the reviewed curriculum is ready, go to **Settings → General → Features** and enable **Discussions**. Then open **Discussions** and use the category management control beside the categories list. Set up:

| Category | Format | Use |
| --- | --- | --- |
| Questions & Answers | Q&A | Concept and course questions |
| Student Project Showcase | Open discussion | Links to builds in student repositories |
| Troubleshooting Help | Q&A | Reproducible symptoms and resolved fixes |
| Ideas & Improvements | Open discussion | Curriculum ideas |
| Announcements | Announcement | Maintainer updates |

The issue forms are tracked under `.github/ISSUE_TEMPLATE`. Use Discussions for conversations and issues for actionable work. [GitHub Discussions setup](https://docs.github.com/en/discussions/quickstart)
